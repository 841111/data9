# 课程设计报告：内容安全班级考勤系统

## 一、需求分析

### 1.1 实验目标

围绕内容安全场景下的人脸识别与活体检测，设计并实现可运行的班级考勤系统，覆盖：

- 日常考勤自动化
- 合照学生批量识别
- 情绪分析统计
- 安全与异常处理

### 1.2 功能需求

- 前端通过浏览器调用摄像头采集人脸并上传。
- 后端完成活体检测、人脸库比对，返回考勤结果。
- 支持上传合照并批量识别人脸，生成学生匹配名单。
- 统计活动参与频次与情绪分类结果。

### 1.3 非功能需求

- 识别效率可满足课堂场景实时性。
- 识别流程支持超时控制。
- 具备常见异常处理与错误提示。

## 二、系统设计

### 2.1 总体架构

采用 BS 架构：

- Browser：负责摄像头采集、图片上传、结果展示
- Server：负责检测识别、统计、数据存储

### 2.2 模块划分

- 人脸引擎模块：人脸检测、活体检测、比对、情绪分析
- 业务服务模块：注册、考勤、合照识别、报表
- 数据模块：学生库、考勤记录、活动统计
- 前端交互模块：注册、考勤、报表展示

### 2.3 数据库设计

核心表：

- `students`：学生信息 + 人脸 embedding
- `attendance`：考勤结果与情绪记录
- `activity_stats`：合照识别活动统计

## 三、关键实现

### 3.1 活体检测策略

- 通过清晰度（拉普拉斯方差）和亮度区间进行基础活体筛查。
- 不满足阈值返回失败并记录原因。

### 3.2 人脸比对策略

- 优先使用 `face_recognition` embedding。
- 无依赖时回退到轻量直方图 embedding。
- 使用距离阈值判定匹配成功与否。

### 3.3 合照识别

- 对上传合照进行多人脸检测。
- 逐人脸进行 embedding 生成与库内匹配。
- 匹配成功后写入活动统计表。

### 3.4 情绪分析

- 基于人脸区域亮度、饱和度、边缘密度做启发式分类。
- 结果用于实验统计，不用于高风险个体决策。

### 3.5 异常处理

- 摄像头不可用：前端捕获异常并提示。
- 上传失败：前端和后端均返回错误信息。
- 识别超时：后端线程超时并返回 408。

## 四、测试与结果分析

### 4.1 测试内容

- 健康检查接口可达。
- 空白图片场景下返回“未检测到人脸”。
- 注册、考勤、合照识别流程可完整执行。

### 4.2 结果分析

- 系统在课程实验中可完成功能闭环。
- 回退 embedding 方案可用但准确率受限。
- 引入高质量模型后识别效果可进一步提升。

## 五、内容安全边界讨论

- 禁止将情绪分析结果用于歧视性或惩罚性决策。
- 采集与存储人脸数据需获取授权，遵循最小化原则。
- 建议生产环境增加鉴权、日志审计、加密与访问控制。

## 六、总结与改进方向

- 已完成实验要求中的三项核心功能与安全异常处理。
- 后续可加入挑战-响应式活体检测、模型量化部署、权限系统与加密存储。
